# CLI UX Rework Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `hwc` plays one character per run, explains itself (help, version, `list`, one-line errors), and shows progress, a summary and log levels, as `docs/superpowers/specs/2026-11-18-cli-ux-design.md` describes.

**Architecture:** Each command is a declaration plus a handler under `src/hwc/cli/`. `src/hwc/cli/args.lua` parses every command from its declaration, and `src/hwc/cli/help.lua` renders help from the same declarations. `src/hwc/ui.lua` owns stdout/stderr, log levels, TTY detection and the progress line. `src/hwc/world/professions.lua` owns profession parsing and every profession label. `src/hwc/cli.lua` shrinks to the dispatcher, keeping `M.main`, `M.stem_name` and `M.wrote_line`.

**Tech Stack:** LuaJIT 2.1 (Lua 5.1, FFI), lfs, dkjson via `hwc.json`, busted 2.3, luacheck 1.2.

**Spec:** `docs/superpowers/specs/2026-11-18-cli-ux-design.md`

## Global Constraints

- LuaJIT 2.1 / Lua 5.1; no new dependencies (FFI ships with LuaJIT).
- stdout carries command results only; progress, warnings and errors go to stderr.
- Usage errors: one line `hwc: <message>`, then `see hwc <command> --help` (`see hwc --help` with no command), exit 2.
- Exit codes: 0 ok, 1 harness failure, 2 usage error; `diff` 0/1/2 as before; `doctor` 1 on a failed check.
- Findings JSON stays format 2 with `header.matrix.combos`; progress and timing never enter a findings file.
- Combo token: `"<Race> <CLASS> <profs>"` with `<profs>` = `none` or the primary professions, lowercase, sorted, joined by `,` (`alchemy,herbalism`).
- Profession rules: `--professions` is a comma list of what the character knows from the start: at most 2 primary, plus First Aid and/or Fishing (uncapped); Cooking can't be named (it's learned via Camping 101: Cooking, as today); no flag = no professions = today's baseline; names sorted canonically; rank 1 of max 75. The simulation's profession behaviour is unchanged.
- `diff.lua`, `report.lua`, `text.lua`, `professions.lua`, `args.lua`, `help.lua` and `summary.lua` are pure (no `io.*` / `os.*`).
- The specs keep calling `cli.main(args, out, err, env)`. `env` gains `tty` (default false) and `clock` (default `os.time`).
- Run the suite with `~/.luarocks/bin/busted`, and lint with `~/.luarocks/bin/luacheck .`, which must report 0 warnings.
- Commit subjects are Conventional Commits, with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Use `feat!:` for the commits that remove commands or flags (Tasks 6 and 7).

## Review Focus

1. **`--race --class WARRIOR`** (a missing value followed by another flag): expect `--race needs a value`, not race = `--class`. Test in Task 4.
2. **`--professions herbalism,` or `--professions ""`**: expect a usage error naming the empty part, never a silent `none`. Test in Task 1.
3. **A warning printed while the progress line is showing on a terminal**: expect the warning on its own clean line, with the progress line redrawn after it. Test in Task 3.
4. **Progress off a terminal (CI)**: expect no `\r` and no escape codes, and one line per change. Test in Task 3.
5. **`hwc run --help` outside a WoW-Pro folder**: expect the help printed and exit 0, because help needs no folder. Test in Task 6.

### Task 4: Argument parser and help renderer

**Files:**
- Create: `src/hwc/cli/args.lua`, `src/hwc/cli/help.lua`, `spec/cli/args_spec.lua`, `spec/cli/help_spec.lua`

**Interfaces:**
- Produces the declaration shape (every command module returns one):
  ```lua
  { name = "run", summary = "...", usage = "--race RACE --class CLASS [--professions LIST] [options]",
    description = "...", hidden = false, needs_folder = true,
    positionals = { min = 0, max = 0, metavar = nil },           -- e.g. diff: {min=2,max=2,metavar="OLD.json NEW.json"}
    options = {
      { name = "race", metavar = "RACE", help = "...", required = true,
        choices = function() return {...} end, see = "hwc list races" },
      { name = "json", flag = true, help = "..." },
      { name = "include", metavar = "PATTERN", filter = true, help = "..." },  -- ordered into opts.filters
      { name = "date", metavar = "D", validate = function(v) return canon | nil, msg end, default_text = "today" },
    },
    notes = { "paragraph", ... },
    check = function(opts) return nil | msg end,                 -- cross-option checks
    run = function(ctx) return status end,                       -- ctx = { opts, ui, env }
    passthrough = false }                                         -- stubs: true, args unparsed
  ```
  - `args.globals(argv) -> g`, where `g = { command, rest, help, version, level }`. It pulls `-h`/`--help`, `--version`, `-q`/`--quiet` and `-v`/`--verbose` out of any position (last of quiet/verbose wins; default `"normal"`). `command` is the first remaining non-option word, and `rest` is the remaining argv.
  - `args.parse(decl, rest) -> opts | nil, msg`. `opts` has one key per option name, plus `positionals` (an array) and `filters` (an ordered `{ kind, raw }` list).
  - `args.suggest(word, names) -> name | nil`: edit distance ≤ 2, nearest first.
  - `help.usage(decls) -> string` and `help.command(decl) -> string`.

  - `--` makes the next word positional.
  - A validator's message is passed through, and `check` runs after everything else.
  - `args.globals({ "run", "-q", "--race", "Dwarf", "--verbose" })` → `command = "run"`, `level = "verbose"`, and `rest = { "--race", "Dwarf" }`.

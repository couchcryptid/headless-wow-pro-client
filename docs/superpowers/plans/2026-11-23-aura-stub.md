# Aura Stub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stub Forever's aura API, which reports no auras, so WoW-Pro's `BUFF` checks run without a Lua error. A `BUFF` step that stalls becomes a harness notice.

**Architecture:** `C_UnitAuras.GetAuraDataByIndex` reads `world.player.auras`, which starts empty. The engine starts reading the `BUFF` tag. When a step with that tag doesn't advance, the driver records a new harness signal, `emulation-gap`, with reason `aura-not-emulated`. That signal is wired through grouping, text, the summary and the web report the same way `arrival-data-gap` is.

**Tech Stack:** LuaJIT 2.1, busted 2.3, luacheck; Preact/Vite report in `web/report` (npm).

**Spec:** `docs/superpowers/specs/2026-11-23-aura-stub-design.md`

## Global Constraints

- Forever has no `UnitAura`; it has `C_UnitAuras.GetAuraDataByIndex` (user, in game, 2026-11-23). Never define `UnitAura`.
- Actions change the world and fire events only, never engine state. Nothing adds to `world.player.auras` in this plan.
- `emulation-gap` is a harness notice: severity `"low"`, out of every count, `report.is_harness` true, grouped by (reason, key).
- Notice reason `aura-not-emulated`, key `<gid>:<line>` (`arrival.step_key(step, gid)`).
- A changed report page needs `npm run build` and the rebuilt `src/hwc/findings/report.html` committed.
- Run `~/.luarocks/bin/busted`, `~/.luarocks/bin/busted --tags=slow` and `~/.luarocks/bin/luacheck src spec` before each commit.

## Review Focus

1. A `BUFF` step that stalls for an arrival reason (e.g. an `R` with `BUFF`): the arrival gap wins, and only one notice is recorded.
2. A `BUFF` step that's an expected manual completion: it stays `manual-completion`, not a notice.
3. A `BUFF` step whose refusal is already explained (`out.explained`): no second signal.
4. `GetAuraDataByIndex` with index 0, a non-number index, or an unknown filter: returns nil, no error.
5. Old findings JSON without the new signal still loads in the web report (fixtures unchanged).
